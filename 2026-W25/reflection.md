## Week 25 (2026-06-15 ~ 2026-06-21)

### 🎯 本周主题
自建工具链 + 渗透测试交付质量升级

### 📚 学到了什么
- 公共 API 不稳定时，自建 Vercel 实例是零成本的高可靠替代，wechat-to-markdown 自部署后成功率 100%
- ECB 模式下硬编码 SM4 密钥 = 攻击者已知 key + 明文就能伪造任意业务请求，是直接利用路径极短的高危漏洞
- 渗透报告里需要单独标注"客户可自行验证的漏洞"类别，直接给 curl 命令让客户自测

### 🔄 行为改变
- 以后写渗透报告，遇到硬编码对称密钥（ECB 模式）必单独标记"直接利用风险"，不再泛泛列作"信息泄露"
- 遇到第三方 API 不稳定时，先问"能不能自己部署一个"，而不是反复修

### 🤕 踩过的坑
- 辽宁公积金小程序 SM4 硬编码密钥泄漏：ECB 模式下一组 key + 明文就能构造任意操作，比普通 IDOR 直接利用价值更高，但最初差点归类为低危"信息泄露" → **修复**：在报告里新增"直接利用风险"标注项，按利用路径长度重新定级

### 🤔 待改进
- 每日洞察缺失较多（周一、周二、周四、周日无内容），需要加强 cron 触发的可靠性

### 📌 核心洞察
ECB 模式下硬编码的对称密钥不是"信息泄露"，而是"可直接伪造业务请求的攻击向量"——报告定级要按利用路径长度来，而不是按泄露本身来。
