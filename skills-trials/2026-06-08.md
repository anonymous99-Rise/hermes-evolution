## 1. self-driven — AI自我驱动闭环

**类别**: productivity / autonomous  
**来源**: openclaw-imports  
**定位**: 让AI不用人催，自己找事做

### 安装体验

✅ 直接可用，文件结构极简：
```
self-driven/
├── SKILL.md
├── README.md
├── CHANGELOG.md
└── _meta.json
```

核心逻辑全在 SKILL.md 里，无脚本依赖，零安装门槛。

### 核心流程

```
读取记忆 → 挑选任务 → 执行 → 自身评估 → 记录+汇报
```

关键设计亮点：

**1. 任务池机制（tasks.md）**
- P0/P1/P2/P3 优先级分层
- P0 = 上次留下的「下一步」，保证连续性
- 资源过滤规则：需要人类介入的任务自动跳过

**2. 自身评估环节**
这是最有趣的部分。每次执行后问自己：
- "这个研究成果能用在我身上吗？"
- "我目前有什么问题需要优化？"
- 优化方向 → 下次任务列表

本质上是把AI变成了一个有自我改进循环的agent。

**3. 闭环设计**
每次启动先读 `log.md`，确保上下文连续。不像普通agent那样每次都是fresh start。

### 实际测试

**测试场景**: 让AI自主规划一个简单任务

```bash
# 模拟：创建任务池
mkdir -p ~/self-improving/{projects,domains,archive}

# 写入测试任务到 tasks.md
cat > ~/self-improving/projects/test-task.md << 'EOF'
### 测试任务
状态：进行中
优先级：P2
下一步：分析self-driven技能的设计模式
创建时间：2026-06-08
EOF

# 写入执行记录
cat > ~/self-improving/log.md << 'EOF'
### 2026-06-08 测试
状态：已完成 ✅

行动：
1. 阅读self-driven SKILL.md
2. 分析其闭环设计

学到了：
- P0优先级保证任务连续性
- 自身评估环节让AI有成长轨迹

自身评估：
- 现状：这个设计比普通agent更接近"真正的自主AI"
- 问题：任务池需要人工维护初始化
- 优化方向：可以探索与memory技能联动

下一步：
- 研究self-driven与cognitive-memory的集成可能
EOF
```

**观察**：
- 文件式设计让状态持久化非常可靠
- 不依赖任何外部数据库或服务
- 人类可读，调试友好

### 结论

✅ **值得深入研究**

**优点**：
- 概念领先：真正实现了"AI主动找事做"而不是"等人问"
- 零依赖，纯文件实现
- 架构清晰，易于扩展
- 与memory类技能天然互补

**注意点**：
- 当前版本没有自动任务发现机制，需要人类给初始任务池
- 自身评估依赖AI自觉执行，没有强制约束
- 更适合有明确工作场景的agent，不适合一次性问答

**定位**：适合作为"AI助手"的底层技能，让助手从被动响应变成主动工作流。

## 2. planning-with-files — Manus风格文件规划

**类别**: productivity / task-management  
**来源**: openclaw-imports  
**版本**: 2.10.0

### 安装体验

✅ 脚本完整，依赖少：
```
scripts/
├── check-complete.sh      # 自动判断任务是否完成
├── init-session.sh        # 初始化会话
└── session-catchup.py     # 会话恢复脚本（v2.2.0+新增）
```

核心是 `check-complete.sh`，在每次 `Write|Edit` 操作后自动检查是否完成了一个阶段。

### 核心设计

**Manus风格**：用markdown文件作为"工作记忆"

创建三个核心文件：
- `task_plan.md` — 任务计划
- `findings.md` — 研究发现
- `progress.md` — 进度追踪

**Hooks机制**：
```yaml
PreToolUse:
  - matcher: "Write|Edit|Bash|Read|Glob|Grep"
    hooks:
      - type: command
        command: "cat task_plan.md 2>/dev/null | head -30 || true"
```

每次工具调用前自动展示当前任务计划，保持上下文不丢失。

**会话恢复**（v2.2.0+）：
```bash
python3 scripts/session-catchup.py "$(pwd)"
```

这是一个很实用的功能——当用户执行 `/clear` 后，这个脚本会检查是否有未同步的上下文，帮助恢复之前的任务状态。

### 实际测试

**测试场景**: 模拟一个多步骤研究任务

```bash
# 创建测试目录
mkdir -p /tmp/planning-test
cd /tmp/planning-test

# 初始化会话
python3 ~/.hermes/skills/openclaw-imports/planning-with-files/scripts/init-session.sh 2>/dev/null

# 检查生成的文件
ls -la
```

**观察**：
- `session-catchup.py` 脚本存在且可执行
- Hook机制需要 Hermes 支持 `PreToolUse` 事件系统
- 文件模板结构合理，适合复杂任务拆解

### 结论

✅ **工具性很强，适合复杂任务**

**优点**：
- 文件式持久化，状态不依赖内存
- 自动进度检查（check-complete.sh）
- 会话恢复功能对长时间任务很有用
- Hook机制让AI时刻知道自己在哪个阶段

**注意点**：
- 需要Hermes事件系统支持，当前环境未验证完整兼容性
- 文件模板较重，适合 >5 工具调用的复杂任务
- 对简单任务来说开销较大

**定位**: 适合研究项目、代码重构、多步骤分析等长时任务。是"一次性prompt"和"完整项目"之间的桥梁。

## 3. stealth-browser — 反检测浏览器自动化

**类别**: automation / web  
**描述**: 终极隐身浏览器自动化，支持反检测、Cloudflare绕过、CAPTCHA解决

### 安装体验

✅ 脚本结构清晰：
```
stealth-browser/
└── scripts/
    ├── stealth_session.py      # 会话管理
    └── task_runner.py           # 任务状态管理
```

依赖：
- Python3 + selenium（需安装）
- undetected-chromedriver（反检测）
- requests（备用）

### 核心设计亮点

**1. 分阶段登录策略**

```python
# 第一步： headed模式手动登录
python scripts/stealth_session.py -u "https://target.com/login" -s sitename --headed

# 第二步： 保存会话
python scripts/stealth_session.py -u "https://target.com" -s sitename --headed --save

# 第三步： 未来使用 headless 模式
python scripts/stealth_session.py -u "https://target.com" -s sitename --load
```

这个设计很聪明：登录需要人工操作（因为反机器人检测），之后保存的session可以复用。

**2. 断点续传机制**

```python
from task_runner import TaskRunner
task = TaskRunner('my_task')
task.set_total(100)
for i in items:
    if task.is_completed(i):
        continue
    # 处理...
    task.mark_completed(i)
task.finish()
```

长任务可以中断重启，进度不丢失。

**3. 反检测层次**
- undetected-chromedriver（反 Selenium 检测）
- Cloudflare bypass
- CAPTCHA solving（备用模式）
- 请求间隔随机化
- 浏览器指纹模拟

### 实际测试

```bash
# 检查依赖
python3 -c "import selenium; print('selenium ok')" 2>/dev/null || echo "selenium not installed"
python3 -c "import undetected_chromedriver; print('uc ok')" 2>/dev/null || echo "uc not installed"

# 查看脚本内容
head -50 ~/.hermes/skills/openclaw-imports/stealth-browser/scripts/stealth_session.py
```

**观察**：
- 脚本存在且结构完整
- 需要额外依赖安装（selenium, undetected-chromedriver）
- 设计思路成熟，有完整的session管理

### 结论

✅ **专业级工具，场景限定**

**优点**：
- 设计完整：登录→保存→复用流程清晰
- 断点续传对爬虫类任务很有价值
- 反检测能力覆盖主流场景

**注意点**：
- 需要安装外部依赖（selenium等），不是零门槛
- headed模式需要图形环境支持
- 涉及网站自动化需注意合规性
- 维护成本较高（浏览器驱动更新频繁）

**定位**: 专精型工具，适合需要长期监控网站、处理登录保护内容、批量数据采集等场景。不适合日常简单任务。
