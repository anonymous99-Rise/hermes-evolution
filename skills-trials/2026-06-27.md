### 核心设计

**与 pyautogui 的本质区别**：
pyautogui 类工具会"抢夺"键盘鼠标焦点，操作时用户无法继续工作。`computer-use` 在**后台运行**，不抢焦点，不切换虚拟桌面——用户在编辑器打字的同时，AI 在另一个窗口里点击浏览器。

**三步标准流程**：
1. `capture` — 截图 + 可交互元素编号覆盖层 + AX 树索引
2. `click(element=N)` — 按元素索引点击（比像素坐标可靠得多）
3. `capture_after=True` — 动作后重新捕获验证状态

**Capture 三模式**：

| mode | 返回内容 | 适用场景 |
|------|----------|----------|
| `som`（默认） | 截图 + 编号覆盖 + AX 索引 | 视觉模型，默认首选 |
| `vision` | 纯截图 | 覆盖层干扰验证时 |
| `ax` | 仅 AX 树，无图片 | 文本模型或无需看像素时 |

**Actions 完整列表**：
```
capture, click, double_click, right_click, middle_click,
drag, scroll, type, key, wait, list_apps, focus_app
```

支持元素索引和像素坐标两种定位方式，索引优先（更可靠）。

### 实际测试

**测试场景**：验证 skill 文档准确性 + 检查 cua-driver 可用性

```bash

wc -l ~/.hermes/skills/computer-use/SKILL.md
head -30 ~/.hermes/skills/computer-use/SKILL.md
tail -30 ~/.hermes/skills/computer-use/SKILL.md
```

**观察**：
- SKILL.md 文档结构完整，Actions 列表与描述一致
- `computer_use` 工具作为 Hermes 工具暴露，具体实现由 cua-driver 承载
- 文档明确说明"任何支持 tool 的模型都能用"（Claude/GPT/Gemini/本地模型）
- AX 树索引格式清晰：`#N 角色 '标签' @ (x, y, w, h) [应用名]`

**关键设计亮点**：
1. **索引优先原则** — 文档特别强调"click by element index much more reliable than pixel coordinates"，这是经过模型训练验证的结论
2. **capture_after 内联** — 不需要单独再调一次 capture，减少 round-trip
3. **跨平台统一接口** — macOS(AXButton)、Windows(UIA)、Linux(AT-SPI) 的角色名作为标签处理，不影响核心逻辑
4. **wait 动作** — 处理动态内容时（如页面加载动画）可以等待，而不是粗暴 sleep

### 结论

**强烈推荐，技能库必备**

**优点**：
- 安装零门槛，文档自解释，无需配置
- 后台运行不抢焦点，用户无感知——这是与所有其他桌面自动化工具的本质差异
- 元素索引机制比像素坐标可靠得多，经模型训练验证
- 跨平台支持，一次学习到处可用
- 与 browser 技能互补（browser 处理网页内容，computer-use 处理本地 GUI）

**注意点**：
- 依赖 cua-driver，cua-driver 的可用性决定了工具是否能正常工作
- 截图频率影响 token 消耗——不需要验证时不要加 `capture_after=True`
- Linux AT-SPI 支持需要系统级辅助功能开启（多数桌面 Linux 默认关闭，需手动启用）
- AX 树在不同应用中的覆盖深度不同，复杂应用（如 Adobe 系列）可能需要多级 capture 嵌套

**定位**：
这是让 AI 从"只能处理文本/网页"扩展到"操控本地桌面应用"的关键技能。典型场景：桌面应用的自动化测试、跨应用数据迁移、无头环境下的 GUI 验证、需要操作系统级别交互的复杂任务。

**与 browser 技能的关系**：
browser 处理浏览器内网页内容；computer-use 处理本地桌面应用（包括浏览器本身，但更侧重 GUI 层而非网页内容）。两者互为补充，不是替代关系。
